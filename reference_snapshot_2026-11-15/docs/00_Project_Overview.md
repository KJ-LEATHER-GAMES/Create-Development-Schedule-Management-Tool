## 2. 目的 / 対象ユーザー / 提供価値

**目的：** 開発案件、ステージ、イベント適用、開催計画・開催状況、開発マイルストーン、証跡・成果物を**単一Excelブックで管理・参照**する。

**対象ユーザー：** 管理担当者（原本を更新）、閲覧ユーザー（設計・開発関係者）、適用判定の最終判断者である機種開発責任者。

**提供価値：** 日程・適用状態・期限超過を一貫したルールで確認し、確認負荷、見落とし、解釈違いの低減を目指す。改善効果は未検証。

## 5. スコープ

**In Scope：** 案件・ステージ・イベント適用／開催回／マイルストーン／証跡の台帳、管理者向け編集と要対応抽出、4ガント、期限超過／開催予定の2一覧、閲覧者別・画面別の絞り込み。

**Out of Scope：** 調査票・新規承認ワークフロー、開催後の宿題完了管理、全件実データ登録、組織の承認制度改正。

**Later：** Qlik Sense実連携、外部自動取込、通知、高度な自動化、網羅的テスト仕様。

## 7. 主要決定事項

| Decision ID（仮） | 決定事項 | 判断理由・効果 |
|---|---|---|
| DEC-001 | 案件→ステージ→イベント。開催回・履歴は別管理 | 適用判断・再開催・変更履歴を区別 |
| DEC-002 | 正本は情報種別ごと。公式日程等は外部、Excel管理情報はExcel | 根拠・整合性の確保 |
| DEC-003 | 4ガント＋期限超過／開催予定の2一覧を提供 | 中長期日程と要対応を可視化 |
| DEC-004 | 日単位90列、旬単位24か月72列。イベント正式名は改行で全件表示 | 固定表示と情報欠落防止 |
| DEC-005 | 原本編集は原則1名、閲覧者は独立絞り込み | 原本保護と利用者別確認を両立 |
| DEC-006 | Box第一候補、SharePoint Online代替。版履歴のみで保全 | 運用簡素化 |
| DEC-007 | 事前PoCなし。実装と並行して技術検証 | 既存の実装経験に基づく判断 |

## 9. 主要制約

| ID | 制約 | 影響 |
|---|---|---|
| CON-001 | Excel単一原本、Windows版／Web版対応 | 共通機能を優先 |
| CON-002 | 編集者原則1名、閲覧者は読み取り専用 | 管理値の保護 |
