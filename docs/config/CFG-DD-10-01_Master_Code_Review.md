## 3. 初期コードカタログ（候補列・未承認の設定データ構造）

| 属性 | 記入ルール | チェック |
|---|---|---|
| `CodeSet` | `MilestoneTypeCode` / `EvidenceType` / `CompareFieldCode` | 3種以外は別の正式変更審議 |
| `Code` | 業務情報オーナーから取得した安定・一意の実値 | 同じCodeSet内で重複不可／削除・再利用不可を推奨（**新補完案**） |
| `DisplayName`、`Meaning` | 表示名称と業務上の意味 | 同義・別名・名称だけのコード判定を避ける |
| `TargetType` / `AllowedTargetTypes` | Project／Occurrence／Milestoneを対象別に具体列挙 | `EvidenceType`・`CompareFieldCode`で各コードごとに指定。マイルストーン種別はMilestoneに使用 |
| `OfficialSource` / `DataType` / `NormalizeRule` | 比較項目に関わる出典・値の型・正規化方針 | `CompareFieldCode`に必須（対象別に未検討の項目を有効にしない） |
| `IsActive` / `EffectiveFrom` | 初期有効性・適用開始（物理列はDraft） | 既存参照があるコードの削除・意味変更をしない |
| `SourceDocument` / `SourceVersion` | 権威あるコード一覧の所在・版 | ファイル・議事録等の根拠リンクを記録 |
| `BusinessOwner` / `Approver` / `ApprovedAt` | 業務管理・承認責任を紐付け | 空欄なら本番投入不許可 |
| `RegisteredBy` / `RegisteredAt` / `ValidationEvidence` | Excel初期登録と検証の証跡 | 実値の追加、重複・無効値・対象外参照拒否を検証 |

このカタログは**業務マスタを登録するためのレビュー用入力テンプレート**であり、実装テーブルの物理方式や列追加を正式承認するものではない。値の収集表：`docs/config/CFG-DD-10-01_Code_Catalog_Template.md`。

## 4. 初期設定の責任分担（未任命の役割案）

| 作業 | 実務担当の推奨ロール | 最終責任・承認の推奨ロール | いま必要な決定 |

| 正式コードの一次収集・根拠提示 | 各公式情報の管理部門／業務データ提供者（**未指名**） | コード体系の**業務責任者**（**未指名**） | 3コードごとの提供元・責任者名・承認者名を指名 |

| 初期Excel台帳へのコード登録 | 開発プロセス管理担当者（原本編集者） | 指名された初期設定責任者 | 実装後の実行責任・作業権限を確定 |
| 入力検証ルール・参照整合性の実装 | 開発担当／Excel技術担当（**未指名**） | 技術検証責任者（**未指名**） | 技術担当・レビュー担当を指名 |

機種開発責任者は**案件別の適用判定の最終判断者**と既決だが、3コード体系全体の承認者とは記載されていない。**自動的にコードオーナーへ指名しない**。

## 6. 採用案の比較（正式採否 CFG10-01 の提案）

| 案 | 管理・承認方式 | 利点 | 代償・限界 |
|---|---|---|---|
| **A（推奨）** | **コードごとの業務オーナーを指名→根拠ある実値＋TargetType許容表を承認→管理者が一括初期登録・検証**。正式版固定後にコード変更を別履歴で追跡。未定義は保存拒否 | 値の出所／承認／登録を分離し再現性が高い。DD10-01の既決制約に適合 | 業務コードの一次資料と担当任命が必要。承認しても実値はまだOpen |
| B | 3コードを個別台帳で管理。各台帳に業務承認と対象別検証を設け、登録時に統合整合性を点検 | 部門ごとの管理を尊重 | 台帳間の整合性チェックと版管理が増える |
| C | 値の収集を実装開始直前まで延期。未登録コードの保存拒否は維持し、使用機能はBlocked | 当面の情報収集作業を減らす | CFG未完了のままで保存系試験や初期データ投入を開始できない |

**承認する範囲**：A/B/Cの運用・初期設定方式。実コード値・個人アサイン・物理テーブル・技術的Passは別の証跡により確定する。
