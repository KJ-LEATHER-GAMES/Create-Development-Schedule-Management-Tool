## 3. 情報種別ごとの正本・照合（OI-01整理）

| 情報種別 | 正本・更新方針 |
|---|---|
| 機種・開発案件の基本情報 | 部品表システムを公式とし、Excel固有の管理情報はExcelで管理。責任者会議議事録は暫定更新根拠になりうる |
| 案件の管理適用・ステージ／イベント適用判定 | 基準ルールは外部（未整備部分あり）、案件別の判定結果はExcel。管理チームが一次判断し、機種開発責任者が最終判定 |
| 開発マイルストーン計画・実績 | 部品表システムが公式。Excelは暫定日・管理メモと参照情報を持つ |
| イベントの計画・実績 | 暫定予定はExcel、確定開催予定は開催通知・正式日程表、開催実績は議事録・実施記録を根拠とする |
| イベント状態 | Excelが管理正本。ただし計画済／開催済／中止の根拠を必要とし、日付超過だけで開催済としない |
| 証跡・成果物 | 社内ファイルサーバーに実体。Excelでは紐付けと参照リンクを保持 |
| 照合・不一致 | 変更を知ったら随時＋月次照合。差異は要確認で記録し、確認後、日付・結果・根拠を残す |

**対象外事項：** 調査票・承認ワークフローは未承認構想。今回の設計範囲へ自動追加しない。

## 7. 整合性上の注記

1. **要件定義Q11の「今後2か月」は、基本設計Q15で「基準日〜翌々月末」として厳密化した。**
2. **要件定義・補完Q6で検討した正常系・異常系の受入方針は、基本設計補完Q33で「主要正常系中心」に更新された。** 詳細な異常系テストは後工程へ移す。
3. **基本設計Q16の任意基準日変更は、Q23で管理担当者のみが操作するものとされた。** 閲覧ユーザーの独立絞り込みとは別の機能。
4. **基本設計Q5の「未計画」は開催回なしと整合するよう、導出状態として設計する案を検討する。** データ表現の細部は未承認。
5. **実装検証はQ27によって後工程へ延期された。** 成立性未検証を「実現確定」と記録しない。
6. **基本設計のExit 6/7と、添付MVP RequirementsテンプレートのEXIT-MVP-REQ-01〜12は別のGateである。** 数値を混用しない。
7. **「開催済」は会議を開催した事実であり、開催後アクションの完了ではない。**
