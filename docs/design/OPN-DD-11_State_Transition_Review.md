## 2. 採用B：データ構造・通常状態遷移

- `tblOccurrence.OccurrenceStatus`を開催回の**現行状態の正本**とする。許容値は`開催予定`／`開催済`／`中止`。**`tblOccurrenceStatusHistory`は新設しない**。
- 開催回の状態が正常遷移して確定した際の根拠を失わないため、`tblOccurrence`へ現行状態に関する**`StatusReason`、`StatusChangedBy`、`StatusChangedAt`、`StatusBasisRef`（任意）、`StatusBasisEvidenceID`（任意）**を論理列として補完する。これは**現在の状態確定情報**であり変更前状態の監査履歴ではない。
- `StatusBasisEvidenceID`を指定する場合はDD10-01の`tblEvidence`で`TargetType=Occurrence`かつ`TargetID=OccurrenceID`となることを検証する。根拠参照形式・保存方法はOPN-DD-14で実装可能性を確認する。

| 現在状態／操作 | 許可・禁止 | 保存条件 |
|---|---|---|
| 新規計画 → 開催予定 | **許可** | 実効適用=`対象`、新`OccurrenceID`とイベント内一意の`OccurrenceNo`、初回日付履歴を確定。初期理由は「計画登録」 |
| 新規計画 → 開催済／中止 | **禁止** | まず開催予定で登録する |
| 開催予定 → 開催済 | **許可** | 管理者の明示操作、実施理由、証跡IDまたは外部根拠参照、実績日付（`tblDateHistory.DateClass=実績`）を伴う |
| 開催予定 → 中止 | **許可** | 管理者の明示操作、中止理由を必須。過去予定日履歴は保持し、日付を自動取消しない |
| 開催予定 → 開催予定 | **状態は不変** | 日付の変更・訂正・取消・再設定は§3の履歴操作とし、状態監査行は作らない |
| 開催済／中止 → 他状態 | **通常操作禁止** | 状態誤登録の訂正はMVPの通常機能で提供しない。OPS-DD11-01で別途運用手順を決める |

**不変条件**：日付経過で自動的に`開催済`へ遷移しない。実効適用=`未判定`／`対象外`では通常の新規計画・状態遷移を拒否する。新しい開催回を作って終端状態の誤登録を「修正」したことにしない。通常状態更新と対応する実績日付履歴の整合確定はOPN-DD-14、部分失敗と復旧はOPN-DD-15の検証対象。

## 3. 採用B：日付取消・再設定（Q09〜Q14を維持）

日付取消は開催回の`中止`ではない。共通日付履歴の正常確定・最大`HistoryID`行から代表日付を導出し、過去行を上書きしない。

| 操作 | 追加する`tblDateHistory`行 | `AfterDate` | `DateClass` | 開催状態 |
|---|---|---|---|---|
| 初回予定設定 | `ChangeType=設定` | 必須 | `暫定`／`正式` | `開催予定` |
| 開催予定日変更 | `ChangeType=変更` | 必須 | `暫定`／`正式` | 不変 |
| 誤日付訂正 | `ChangeType=訂正` | 正しい日付 | 当該状態に整合する区分 | 不変。過去行は保持 |
| 開催予定日の取消 | `ChangeType=取消` | **空欄** | **空欄** | `開催予定`のまま |
| 取消後の再設定 | **`ChangeType=設定`再利用** | 必須 | `暫定`／`正式` | `開催予定`のまま。UIでは再設定と表示 |
| 開催済への遷移時 | `ChangeType=変更` | 実績日付必須 | `実績` | 管理者操作で`開催済`へ |

取消後は**代表日付＝空欄**となり、再設定の新しい正常確定履歴の値だけを復帰させる。`OccurrenceID`・`OccurrenceNo`は変更しない。`開催済`／`中止`の**通常の予定変更・取消・再設定**は禁じるが、既存Q13に基づく**日付の事実誤記に限った管理者の根拠付き訂正**は別操作として扱い、`tblDateHistory`を追記する。状態の誤登録訂正は§7の未解決課題であり、日付訂正を通じて状態を変更してはならない。

## 4. 採用B：複数開催回のイベント要約

イベント単位の要約は**導出値**。`tblOccurrence`各行の状態や過去履歴を書き換えない。実効適用=`対象`の場合の優先順位：

| 開催回の組合せ | イベント要約 | 表示上の要件 |
|---|---|---|
| 0件 | **未計画** | 架空開催回を作らない |
| `開催予定`が1件以上 | **計画済** | 予定回を優先。全回の状態内訳と回数を保持 |
| 予定0件、`開催済`が1件以上 | **開催済** | 中止回が混在しても開催事実を隠さない |
| 予定0件、開催済0件、`中止`が1件以上 | **中止** | 全回が中止のとき |

同一カテゴリ内は`OccurrenceNo`降順で明細の表示順を決める。回次が重複していれば不整合として保存・表示の検証対象。開催予定の代表日付が取消で空欄でも**計画済**であり、管理画面では別に「日付未設定」を表示する。実効適用が`未判定`／`対象外`の場合は要約4値を通常業務表示に割り当てず、適用状態と過去回の内訳を管理用に表示する。G01〜G04／L01・L02の出力契約・抽出は**OPN-DD-12**で別途確定する。

## 5. 採用B：非適用化と再適用

| 管理操作 | 実効`対象` | 実効`未判定`／`対象外` |
|---|---|---|
| 開催回の新規／再開催登録 | 許可（重複疑いの警告・確認） | **禁止** |
| 開催予定回の日付設定・変更・取消・再設定 | 許可 | **禁止** |
| 開催予定→開催済／中止 | 許可（根拠必須） | **禁止**。自動中止もしない |
| 既存回・日付履歴の閲覧 | 許可 | **許可**。過去の事実を保持 |
| 過去日付の事実誤記訂正 | 管理者の根拠付き訂正 | **管理者の根拠付き訂正のみ**。計画更新の代用不可 |
| 終端状態の誤登録訂正 | 通常画面では禁止 | **通常画面では禁止**。OPS-DD11-01へ |
| DD10-01証跡登録、照合・再照合 | DD10-01規則の下で許可 | **許可**（過去事実の追補） |

実効適用はステージ×イベントの**保存済み判定から導出**し、開催回の状態を自動書換えしない。再適用時は既存開催予定回の確認を促す**管理者警告**を出す。判定変更により`OccurrenceID`・回次・共通日付履歴を削除・再採番しない。
