## 2. 共通表示データ契約 [DD12-01承認／A案に採用]

### 2.1 派生レコード・キー

保存対象の**新しい正本テーブルは追加しない**。共通表示データは内部的に次の**論理レコード**として派生させる（実装上の結合/キャッシュ構造はOPN-DD-14/15で検証）。

| 論理レコード | 1件の粒度/内部キー | 最小フィールド・計算 |
|---|---|---|
| 案件 | `ProjectID` | `ModelCode`, `ProjectCode`, `ManagementApplicability` |
| ステージ | `ProjectStageID` | `ProjectID`, `StageID`, `StageApplicability` |
| イベント適用 | `ProjectEventID` | `EventTypeID`, `ProjectStageID`, `EventApplicability`, **実効適用**（親×イベントから導出）, 正式イベント名 |
| 開催回 | `OccurrenceID` | `ProjectEventID`, `OccurrenceNo`, `OccurrenceStatus`, 最新正常確定`HistoryID`, **代表日付（nullable）**, `DateClass` |
| マイルストーン | `MilestoneID` | `ProjectID`, `MilestoneTypeCode`, `MilestoneName`, `IsActive`, 最新正常確定`HistoryID`, **代表日付（nullable）**, `DateClass` |
| 照合差異 | `ReconciliationID` | 対象種別/ID、最新正常確定`ReviewID`、導出`ReviewStatus` |

**不変条件**：実効適用は保存しない。日付は`HistoryID`で求める。`TargetType`と`TargetID`は型別に正本照合する。正本上の親なし・同一ID重複・履歴確定異常を発見した場合は「正常表示」と見なさず管理者へ異常を明示する。エラー時の全体/部分停止粒度はOPN-DD-15で決める。

### 2.2 共有計算・軸定義 [DD12-01承認／技術留保あり]

1. **旬**：各月1〜10日を上旬、11〜20日を中旬、21日〜月末を下旬。境界日10/11/20/21日を含む。24か月を月初から72旬とする。
2. **90日**：管理者設定の開始日を第1列として連続90暦日（両端含む）。表示列数は変更しない。
3. **開始期間**：G01/G03/G04旬はそれぞれ独立した開始月、G02/G04日はそれぞれ独立した開始日を管理者設定として保持。G04旬・日モードの設定も互いに独立（B/Cにおいても同じ）。閲覧者の絞り込みでは変更できない。
4. **表示基準日**：L02の基準日は管理者が変更、初期値はシステム当日。翌々月末は「基準日の属する月から2か月後の月末」。例：2026-11-16→2027-01-31。L01はどの画面の開始日・L02基準日にも依存しない。
5. **日付未設定**：`AfterDate`空欄の最新取消や履歴なしの場合、開催回は存在するが時間軸には**点を打たない**。未計画（開催回0件）とは区別する。
6. **表示時刻の比較**：時刻を除いた業務日付同士で比較。システム当日の現地タイムゾーン/端末依存性はOPN-DD-14/15と受入に引き継ぐ（**業務日付＝日本時間**を実装上採用する案。正式確認前は未確定）。
7. **安定ソート**：表示行は`ModelCode`,`ProjectCode`,`StageID`、セル内は代表日付、`EventTypeID`, `OccurrenceNo`, `OccurrenceID`の順に安定化（識別子比較方式は実装前に固定）。表示文字列のみで重複削除しない。

### 3.1 セル内容・重複/表示外 [DD12-01 A承認]

- 同じイベント種別でも複数`OccurrenceID`が同日/同旬なら**全開催回を表示**。重複名称でも名前を1件に集約しない。表示例：`正式イベント名（第1回／11-18／開催予定）`、`正式イベント名（第2回／11-18／開催予定）`。
- ガントの開催予定回は`DateClass=暫定/正式`で区別し、開催済回は`実績`を区別する。表示スタイルの実色・アイコン/行高調整は実装検証対象、確定を主張しない。
- 中止回は履歴を保持するが、**A案ではガント標準の現行日程セルに描画しない**。管理者案件詳細から中止理由/履歴を参照可能。B案の代替は§8。
- 代表日付なしの開催予定回は**ガントの時刻軸外**とし、管理者「日付未設定」に抽出する（§5）。
- 管理非対象案件、対象外ステージは既定除外。ただし原本管理画面から閲覧/確認できる（原本削除なし）。実効非対象イベントは実際に開催回が存在しても**日程マークを標準ガントに出さない**。
- 表示期間外のデータは該当セルに描画しない。開催回自体は変更しない。元のIDは詳細参照に用いる。

## 4. L01・L02の厳密抽出 [DD12-01承認／A案に採用]

**定義**：`ValidDate(o)` = 当該`OccurrenceID`の最新正常確定`tblDateHistory`から導出された代表日付が非Null。`EffTarget(o)` = 親案件が管理対象かつイベント実効適用=`対象`（案件管理適用が`未判定`の場合も安全側で予定一覧から除外する承認済み規則）。`Plan(o)` = `OccurrenceStatus=開催予定`。

- **L01（期限超過）**：`EffTarget(o) AND Plan(o) AND ValidDate(o) AND RepresentativeDate(o) < SystemToday`。
- **L02（開催予定）**：`EffTarget(o) AND Plan(o) AND ValidDate(o) AND BaseDate <= RepresentativeDate(o) <= EndOfMonth(BaseDate + 2 months)`。
- 各一覧の**一意キーは`OccurrenceID`**。1回の開催が同じ画面に複数行となる結合結果を許さず、名称/日付が一致する**異なる開催回は別行**として保持する。
- **日付の両端**：L01は前日まで（当日は含まず）。L02は基準日と翌々月末の両端を含む。
- L02の基準日を過去に変更したときは、**過去日付も期間内なら一覧へ含まれ得る**。L01（常に今日で期限超過）との重複は異常ではない。必要ならタイトルに基準日を明示する（基準日に今日以降という新制約は追加しない）。
- `開催済`（実績日付あり）と`中止`は両一覧から除外。`開催予定`でも代表日付未設定なら両方から除外して**管理者未設定抽出へ**。イベント自体が未計画＝開催回0件も両方に出さない。

## 7. 表示更新・検証・トレーサビリティ

- **鮮度**：正本保存成功後、共通表示データ再生成。失敗なら原本保存結果は維持し、`DisplayRefreshStatus=失敗`等の異常と最終正常更新時刻を管理者/閲覧者に明示する（物理実現・エラー時復旧はOPN-DD-15）。成功時は各画面が同一正常更新版を参照することを検証。
- **異常**：孤立FK、同一`OccurrenceID`重複、正常確定履歴の選定不能、ステージ所属不一致があれば整合性エラー。**不正データを予定イベントへ黙って昇格しない**。
- **技術留保**：Excel Windows/Web・Box/SharePointでの独立フィルター、90列・改行/全文・動的行高、日付計算/性能、再生成の競合/鮮度は未検証。**A案承認だけではNot Testedから変更しない**。
