## CONS-DD-01：イベント適用行の生成タイミング

### 1. 変更対象と先行・後発判断

- **先行判断（基本設計GrillMe Q04、B）**：案件登録時は全標準ステージの適用行を`未判定`として作成し、イベント適用行はステージが`対象`となってから生成する。
- **後発判断（詳細設計GrillMe Q05、A）**：案件登録時に**全イベント種別**について適用行を作成し、初期値は`未判定`とする。
- **共通で保持する確定事項**：案件登録時の全ステージ行生成、イベント種別の所属ステージ固定、実効対象外と保存判定の分離、開催回は計画時生成、既存開催回・履歴は保持。
- **変更理由**：**未記録**（技術的な推測をユーザー決定の理由として代入しない）。

### 2. 影響分析（Draft）

| 変更観点 | 影響・確認事項 |
|---|---|
| 初期レコード数 | Q05方式は全イベント種別を全案件へ生成し、登録時の行数が増加。データ規模は未定義（OI-DD-01） |
| イベント適用編集 | ステージが未判定／対象外でもイベント判定行は存在し得る。実効状態の算出・編集権限の整理が必要 |
| マスタ差分同期 | 新イベントマスタを既存案件へ同期する条件が変わる。既存判定値・IDを保持する必要がある |
| データ整合 | `tblProjectEvent`と`tblProjectStage`の所属StageIDの一致、二重行防止が必要 |
| 閲覧・要対応抽出 | 未判定イベント行の存在を開催計画と誤認しないこと、未計画は適用対象＋開催回ゼロで導出すること |
| 性能 | 初期行数増のExcel性能影響は**未検証**。想定件数の設定（旧EXIT-06）は保留中 |
| 既存文書 | 基本設計Q04の改訂履歴、`Decision_Log.md`の前後関係、`MVP_Requirements.md`のREQ-MVP-004と関連説明を確認・必要に応じ変更 |
