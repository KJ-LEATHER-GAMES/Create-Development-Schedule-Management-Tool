## 2. 運用ルール（確認済み）

| 項目 | 確定事項 | 残る詳細 |
|---|---|---|
| Excel更新責任 | **管理担当者が一元更新**。内容の正確性に対する責任と入力作業責任は分離する | SRC-02/03の判定権限者は特定済み。他情報種別の内容責任者は未確認 |
| 更新起点 | 変更情報を把握した際、管理担当者が手動で確認・反映する | 具体的な情報伝達経路／更新期限 |
| 定期照合 | **月1回**、正式情報源とExcelの整合性を確認。変更情報入手時は随時確認する | 各情報種別への適用方法、月次実施日 |
| 速報と正式値 | 議事録の速報等と部品表システムの正式値は区別し、速報で正式値を無条件に上書きしない | 画面上の表示優先順位 |
| エビデンス必須 | 管理要否・適用要否判定、正式日程変更、確定イベント計画・開催実績、開催ステータス変更 | 資料登録の技術的な強制方法 |
| エビデンス任意等 | 暫定・調整中情報は根拠を記録するが資料リンクの必須化は未決定。表示順・管理用メモは原則任意 | 暫定情報の根拠形式 |
| 不一致 | 不一致を**要確認**として記録し、正本と根拠の確認後にExcelを修正。確認日・対応結果・根拠を保持 | 不一致管理の列・入力画面・修正期限 |
| 資料参照 | Excel内の独立一覧で資料リンクと関連対象を管理。資料本体はExcelに埋め込まない | パス形式、改版追跡、アクセス権確認 |

### 管理要否・イベント適用要否の判定責任（Q14〜Q17反映）

| 役割・対象 | 運用方針 | 決定状態 |
|---|---|---|
| 一次判断 | 開発プロセス管理部門が機種・開発案件ごとに一次判断を行う | **暫定業務フロー案** |
| 最終判断権限者 | 別部門の**機種担当＝機種開発責任者** | **確定（Q14・Q16）** |
| 最終判断手段 | 機種別の調査票を利用する予定 | **暫定業務フロー案／未承認** |
| 調査票を使用する場合の証跡 | **最終判断者・判断日・判定結果**を記録した回答済み調査票。追加承認工程は原則不要 | **条件付きの方式確定（Q17-A）** |
| 証跡の保管 | 社内ファイルサーバーに保管し、Excelのエビデンス一覧から参照する | **既存保管方針に基づく適用案** |
| Excel登録 | 管理担当者が最終判断結果をExcelに登録する | **確定（既存運用）** |
| 判断基準 | 正式な規程・条件は未整備／未特定 | **未確定** |
| 本人確認 | 調査票の記載が機種開発責任者による最終判断であると識別できる仕組みが必要 | **方式未確定** |

> **重要：** Q17のA回答は「調査票を採用する場合の証跡方式」を確定したもので、調査票による一次／最終判断フロー全体を正式承認したことを意味しない。今後の運用承認までは暫定案として管理する。

**データ整合性上の提案（未承認）：** 一次判断と最終判断は別管理とし、最終判断前の正式な判定値は「未判定」として扱う。調査票における状態区分・差戻し・版管理は次の設計工程で定義する。

### 不一致処理

1. 月次照合または随時確認で不一致を発見する。
2. 不一致を「要確認」として記録する。
3. 情報種別に対応する正本・エビデンスを確認する。
4. 管理担当者がExcelの該当値を修正する。
5. 確認日、対応結果、根拠を記録する。

※Excelが正本である項目を外部情報だけで自動上書きしない。
